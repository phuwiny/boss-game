# สเตจ 4 Haunted House — Design

วันที่: 2026-10-22 · สถานะ: ร่างรอพินอนุมัติ · เอกสารคู่กัน: [Codex visual handoff](2026-10-22-stage4-codex-visual-handoff.md)

## 1. เจตนาและเหตุผล

พินอยากให้เกมมี **ฉากที่ท้าทายและมีอะไรแปลกใหม่** พร้อม **การเคลื่อนไหวที่ลื่นไหลกว่าเดิม** โดยเลือกทำเป็น **สเตจที่ 4 แยกออกมา** แทนการแก้ 3 สเตจเดิม เพื่อไม่กระทบสถิติที่ผู้เล่นทำไว้

ความท้าทายของสเตจเดิมมาจาก "เก็บให้ครบ/เก็บให้เร็ว" มากกว่าตัวฉาก สเตจ 4 จึงเปลี่ยนโจทย์เป็น **puzzle การหาทางไปเก็บเหรียญ** ในบรรยากาศใหม่

## 2. สิ่งที่พินกำหนด

- **ธีม:** บ้านผีสิงฮัลโลวีน ดูลึกลับ ตกแต่งด้วยฟักทองประหลาด
- **ศัตรู:** ฟักทอง บางลูกโจมตีด้วยลูกไฟได้
- **แสง:** มืดสลัวเล็กน้อย (ไม่ใช่มืดจนมองไม่เห็นทาง)
- **กลไกหลัก:** สวิตช์สลับ **บล็อกสีม่วง / สีส้ม** เพื่อสร้างทางไปต่อ (ยกเลิกไอเดียประตูวาร์ป)
- **กลไกรอง:** **แพลตฟอร์มเลื่อนขึ้นลง** สำหรับเหรียญที่อยู่สูง
- **ความสูงด่าน:** เท่าสเตจป่า (18 แถว) กล้องไม่เลื่อนแนวตั้งเพิ่ม
- **เหรียญ:** **วางตายตัว** ตามที่ออกแบบ puzzle เหมือนเดิมทุกวัน (ไม่สุ่มรายวัน)
- **Motion:** ปรับตอน **วิ่ง กระโดด แพ้** และ **asset ในฉาก** — **เฉพาะสเตจ 4 ก่อน**
- **Workflow:** ทำแผนก่อนลงมือ; **งานภาพทั้งหมด handoff ให้ Codex** สร้างด้วย imagegen skill
- **แนวทาง implementation:** ต่อยอด engine เดิม (Approach A ด้านล่าง)

## 3. Goals / Non-goals / Anti-goals

**Goals**
- สเตจ 4 เล่นได้ครบทั้งโหมดปกติและโหมดจับเวลา ทั้ง 3 ตัวละคร บันทึกสถิติแยกเหมือนสเตจอื่น
- ผู้เล่นมีช่วง "อ๋อ" จากการสลับสวิตช์ม่วง/ส้มอย่างน้อยหนึ่งครั้งต่อห้อง
- ตัวละครในสเตจ 4 ขยับลื่นกว่าเดิมอย่างเห็นได้ชัดตอนวิ่ง กระโดด ลงพื้น และแพ้
- ทุก asset ใหม่มี fallback: โหลดภาพไม่ได้ยังเล่นได้ครบ

**Non-goals (รอบนี้)**
- ไม่เปลี่ยน motion/ภาพของสเตจ 1–3 และมินิเกม
- ไม่ทำบอสใหม่ ไม่ทำประตูวาร์ป ไม่ทำกล้องเลื่อนแนวตั้ง
- ไม่ทำ leaderboard/backend
- ไม่แต่งเพลง mp3 ใหม่ในรอบนี้ (ดูข้อ 8)

**Anti-goals (ถ้าเกิดถือว่าล้มเหลวแม้ระบบจะทำงาน)**
- puzzle ถูกข้ามได้ง่ายด้วยความสามารถตัวละคร (โดยเฉพาะ Mew ที่กระโดด 2 ชั้นและลอยตัวได้) จนไม่ต้องใช้สวิตช์
- ผู้เล่นติดตาย (softlock): ติดอยู่ในบล็อก หรือสลับสวิตช์แล้วกลับไปไม่ได้
- ความมืดทำให้มองหนาม/ลูกไฟไม่ทัน จนโดนแบบไม่ยุติธรรม
- ท่าใหม่ทำให้สัดส่วนตัวละครเพี้ยน (บทเรียนจาก run5–8 ที่ถูกยกเลิกเมื่อ 2026-10-16)
- สเตจ 1–3 เปลี่ยนพฤติกรรมหรือเฟรมเรตแย่ลง

## 4. ข้อจำกัดจาก codebase

- ด่านเป็นตารางสัญลักษณ์ 18 แถว ต่อ section ซ้ายไปขวา (`js/level.js` `CQ.parseLevel`) สเตจลงทะเบียนผ่าน `CQ.STAGES.push({...})` ในไฟล์ `js/stage-*.js`
- ปัจจุบัน flag `boss: true` ผูก "มีบอส" กับ "ยิงพลังได้" ไว้ด้วยกัน (`stepBossStage` ใน `js/main.js`) สเตจ 4 ต้องยิงได้แต่ไม่มีบอส → ต้องแยก flag
- แพลตฟอร์มเคลื่อนที่รองรับเฉพาะแนวนอน (`minX/maxX` ใน `parseLevel`)
- `tools/check-level.js` ตรวจ reachability แบบไม่คิดสถานะสวิตช์ และจำลองรางเป็นแผ่นไม้นิ่ง
- `g.landSquash` ถูกคำนวณใน `js/main.js` แต่ `drawHero` ไม่ได้ใช้ (ยังไม่มี squash/stretch จริง)
- ท่าตัวละครเป็นภาพ raster 9 ท่า logical frame 54×48, backing 108×96, anchor `ax` เดิม (`js/2026-10-15_character-art.js`, `js/sprites.js`)
- เกมไม่มี build step ไม่มี dependency; ต้องเปิดผ่าน `file://` ได้; มีชุด QA ด้วย Playwright ใน `tools/` และเกณฑ์ performance RAF p95 จากรอบ 2026-10-16
- สถิติใน localStorage แยกตาม `stage.id` อยู่แล้ว → id ใหม่ได้สถิติแยกอัตโนมัติ

## 5. Approaches ที่พิจารณา

| | แนวทาง | ได้ | เสีย |
|---|---|---|---|
| **A (เลือก)** | ต่อยอด engine เดิม: เพิ่มสัญลักษณ์/tile/enemy ใหม่ ใช้ physics, HP, ลูกไฟของบอสที่มีอยู่ | ใช้โค้ดที่ผ่าน QA แล้ว, งานน้อยสุด, check-level ขยายต่อได้ | แตะไฟล์กลาง (`world.js`, `render.js`, `main.js`) ต้องรัน regression สเตจ 1–3 |
| B | โมดูลสเตจ 4 แยก มี world/render ของตัวเอง | ไม่กระทบสเตจเดิมเลย | physics/HUD/สถิติซ้ำสองชุด แก้บั๊กสองที่ |
| C | Refactor เป็นระบบ entity กลางก่อน | สะอาดระยะยาว | รื้อของที่ผ่าน QA หลายรอบ เสี่ยงสูง ประโยชน์ยังไม่ได้ใช้ |

**พินเลือก A** เหตุผล: กลไกทั้งหมดต่อจากของเดิมได้ตรง ๆ และมีชุด QA จับ regression อยู่แล้ว

ลำดับงาน: gameplay เล่นได้ก่อนด้วยภาพ procedural ชั่วคราว → Codex ทำภาพตาม handoff ขนานกัน → นำภาพเข้าเกม

## 6. การออกแบบ gameplay

### 6.1 ข้อมูลสเตจ

```js
CQ.STAGES.push({
  id: 'haunted', no: 4, name: 'Haunted House', th: 'บ้านผีสิง', theme: 'haunted',
  sections: SECTIONS,
  hp: 5,              // ระบบพลังชีวิตแบบ Boss Stage
  shoot: true,        // ยิงพลังได้ (flag ใหม่ แยกจาก boss)
  fixedCoins: true,   // ใช้เฉพาะเหรียญ 'o' ที่วางในด่าน ไม่สุ่มรายวัน
  items: [...],       // ไอเทมวางตายตัวเช่นกัน (ดู 6.6)
  dark: { ... },      // ค่าความมืด (ดู 6.5)
  motion: 'v2'        // เปิด motion ใหม่เฉพาะสเตจนี้ (ดู 7)
});
```

- ชื่อ field ข้างบนเป็น *ข้อเสนอ* ผู้สร้างเปลี่ยนได้ถ้าเข้ากับโค้ดมากกว่า
- เพิ่ม stage ปุ่มที่ 4 ในหน้าแรกตามกลไก `CQ.STAGES` เดิม (วนซ้าย/ขวาได้อยู่แล้ว)

### 6.2 บล็อกสวิตช์ม่วง/ส้ม

- **สถานะรวมทั้งด่าน** (global) ค่าเดียว: `'purple'` หรือ `'orange'` เริ่มต้นที่ `'purple'`
- บล็อกสีที่ตรงกับสถานะ = ทึบ (ยืน/ชนได้) อีกสี = **โปร่ง** วาดเป็นกรอบเส้นประจาง ๆ ให้เห็นว่าสลับแล้วทางจะเปิดตรงไหน
- **สวิตช์** เป็นบล็อกทึบ กดได้ 2 วิธี: กระโดดโหม่งจากด้านล่าง หรือยิงพลังโดน; มี cooldown สั้น (~0.3 วิ) กันกดเบิ้ล
- ทุกสวิตช์ในด่านสลับสถานะเดียวกัน (ไม่มีสวิตช์แยกกลุ่มในรอบนี้)
- **กันติดในบล็อก:** ถ้าตอนสลับ บล็อกที่จะกลายเป็นทึบซ้อนกับตัวผู้เล่น/ศัตรู บล็อกนั้นยังคงโปร่งจนกว่าจะไม่ซ้อนแล้วค่อยทึบ (แนวเดียวกับหมูป่า `safe` ใน `js/world.js`)
- **เช็กพอยต์จำสถานะสวิตช์** ตอนแตะธง; พลาดแล้วกลับมาที่สถานะนั้น
- **Accessibility:** สองสีต้องแยกด้วยรูปทรงด้วย ไม่ใช่สีอย่างเดียว — ม่วงมีลายพระจันทร์/วงกลม, ส้มมีลายสี่เหลี่ยม/หน้าฟักทอง
- สัญลักษณ์ใหม่ในตารางด่าน (ข้อเสนอ): `M` บล็อกม่วง, `O` บล็อกส้ม, `T` สวิตช์ (ตัวอักษรที่ยังไม่ถูกใช้)
- เสียง: เอฟเฟกต์ "คลิก + เสียงผี" สังเคราะห์ด้วย Web Audio ตาม `js/audio.js`

### 6.3 แพลตฟอร์มเลื่อนขึ้นลง

- รางแนวตั้ง สัญลักษณ์ใหม่ (ข้อเสนอ) `|` วางเป็นคอลัมน์ แพลตฟอร์มกว้าง 3 ช่องเหมือนแนวนอน วิ่งขึ้น-ลงตามราง มีจังหวะหยุดที่ปลาย (ค่าเริ่มเหมือนแนวนอน: speed 80, wait 0.5)
- ผู้เล่นยืนบนแพลตฟอร์มต้องติดไปด้วยทั้งขาขึ้นและขาลง ไม่จมทะลุ ไม่กระตุก
- ไม่มีหนามที่ปลายทางบน/ล่างที่บีบผู้เล่นได้ (กติกาตรวจใน check-level)

### 6.4 ฟักทอง

สองชนิด (ข้อเสนอของ Claude — พินบอกแค่ "บางอันยิงลูกไฟได้"):

| ชนิด | สัญลักษณ์ | พฤติกรรม | วิธีจัดการ |
|---|---|---|---|
| **ฟักทองกระโดด** | `k` | กระโดดไป-กลับเป็นจังหวะ | เหยียบหัว = แตก, ยิงโดน = แตก |
| **ฟักทองยิงไฟ** | `j` | อยู่กับที่ หันหาผู้เล่นในระยะ; **ตาเรืองแสง + สั่นก่อนยิง ~0.6 วิ** แล้วยิงลูกไฟตรงไปหาผู้เล่น 1 ลูก; คูลดาวน์ ~2.5 วิ | ยิงพลังโดน 3 ครั้งแตก, เหยียบหัวได้ (แตก) |

- ลูกไฟใช้ระบบ `Boss.fireball`/`stepShot`/`shotHits` เดิม (`js/boss.js`) แต่สีต่างจากบอส (เขียวผี/ม่วง) เพื่อแยกออก
- โดนตัวฟักทองหรือลูกไฟ = เสียพลังชีวิต 1 ขีด + อมตะ 1.5 วิ (ระบบ HP เดิม) โล่ Aclaire กันได้ 1 ครั้งเหมือน Boss Stage
- ฟักทองยิงไฟมี **แสงของตัวเอง** ในความมืด (ดู 6.5) ผู้เล่นจึงเห็นได้แม้อยู่ไกล
- ค่าตัวเลขทั้งหมดอยู่ต้นไฟล์ใหม่เป็นค่าคงที่ (แนวเดียวกับ `BOSS`, `ROCK`) เพื่อจูนง่าย

### 6.5 ความมืดสลัว

- ชั้นเงาสีม่วงเข้มทับฉาก (alpha ราว 0.45–0.55) มี **วงแสงรอบผู้เล่น** รัศมีราว 5–6 ช่อง ขอบนุ่ม
- แหล่งแสงเพิ่ม: ฟักทองยิงไฟ, ลูกไฟ, เทียน/โคมในฉาก, สวิตช์
- **ห้ามมืดจนอ่านไม่ออก:** หนาม, ขอบบล็อกสวิตช์, เหรียญ ต้องมองเห็นได้นอกวงแสง (เหรียญเรืองแสงเล็กน้อย)
- ทำด้วย offscreen canvas เดียว อัปเดตแบบไม่สร้าง gradient ใหม่ทุกเฟรมเกินจำเป็น ต้องผ่านเกณฑ์ RAF p95 เดิม (+20% เทียบ baseline) ทั้ง desktop และ viewport มือถือในชุด QA
- มินิแมพแสดงเหรียญที่ยังไม่เก็บตามปกติ (โจทย์คือหาทางขึ้นไป ไม่ใช่หาว่าเหรียญอยู่ไหน)

### 6.6 ผังด่าน เหรียญ และไอเทม

- ความยาว (ข้อเสนอ): **6 ห้อง/section ราว 220–260 ช่อง** — ระหว่าง Boss Stage (176) กับสเตจปกติ (~350) เพราะ puzzle ใช้เวลาต่อช่องมากกว่า
- แต่ละห้องมี puzzle สวิตช์อย่างน้อย 1 จุด ความยากไล่ขึ้น: ห้องแรกสอนกลไก (สลับแล้วทางเปิดตรงหน้า) → ห้องท้ายต้องสลับหลายครั้งระหว่างทาง และใช้แพลตฟอร์มแนวตั้งร่วม
- เช็กพอยต์ที่ต้นทุกห้อง
- **เหรียญวางตายตัว** รวม **40 เหรียญ** (เท่าเป้าหมายสเตจปกติ) — เหรียญ "ยาก" อยู่หลังกลไกสวิตช์หรือบนที่สูงที่ต้องใช้แพลตฟอร์มแนวตั้ง
- **โหมดจับเวลา:** ใช้ผังและเหรียญชุดเดียวกัน (40) เวลา 120 วินาที เก็บได้มากสุด (ไม่เพิ่มเป็น 80 เพราะเหรียญผูกกับ puzzle)
- **ไอเทมวางตายตัว:** หัวใจ 3, เห็ด 1; **ไม่มีปีกและดาว** เพราะปีก (กระโดดเพิ่ม) ข้าม puzzle ได้ และดาว (อมตะ) ลบความท้าทายจากฟักทอง
- `?seed=` และด่านประจำวันไม่มีผลกับผังสเตจ 4 (ยังแสดงป้ายวันที่ตามเดิม และบันทึกสถิติรายวัน/ตลอดกาลเหมือนสเตจอื่น)
- **ต้องออกแบบโดยคิดถึง Mew:** กระโดด 2 ชั้น + ลอย 4 วิ ข้าม puzzle ได้ง่ายถ้ามีพื้นที่โล่งด้านบน → ห้อง puzzle ใช้ **เพดานและผนังบล็อกสวิตช์** ปิดเส้นทางลัด

### 6.7 ตัวตรวจด่าน (`tools/check-level.js`)

ต้องตรวจได้ว่า:
1. ทุกเหรียญ/ไอเทมวางตายตัวในสเตจ 4 **เก็บได้จริงด้วยทั้ง 3 ตัวละคร** โดย BFS บน (ตำแหน่ง, สถานะสวิตช์) — การโหม่งสวิตช์เป็น edge ที่เปลี่ยนสถานะ
2. รางแนวตั้งจำลองเป็นจุดยืนได้ทุกความสูงตลอดราง (แนวเดียวกับที่รางแนวนอนถูกจำลองเป็นแผ่นไม้นิ่ง)
3. ไม่มีจุดที่สลับสวิตช์แล้วกลับไปเช็กพอยต์ล่าสุดไม่ได้ (softlock)
4. ฟักทองอยู่บนพื้น, สวิตช์โหม่งได้จากด้านล่าง
5. **ตรวจเตือน (ไม่ fail):** เหรียญที่ Mew เก็บได้ *โดยไม่ต้องสลับสวิตช์* แต่ Bobo ต้องสลับ — ให้ผู้ออกแบบด่านดูว่าเป็นทางลัดที่ไม่ตั้งใจหรือไม่

เปิดด้วย `stage.motion === 'v2'` เท่านั้น สเตจ 1–3 และมินิเกมต้องได้ภาพเหมือนเดิมทุกพิกเซล

- **Squash/stretch:** ยืดตอนกระโดดขึ้น, ยุบตอนลงพื้น (ต่อ `g.landSquash` ที่มีอยู่แล้วเข้ากับ `drawHero`), คืนรูปแบบ ease
- **เอียงตัว** ตามความเร่ง/ความเร็ว เล็กน้อย; **ฝุ่น** ตอนเบรก/กลับตัว/ออกตัว
- **ท่าแพ้:** หยุดภาพสั้น ๆ (hit-stop ~0.12 วิ) → ตัวเด้งขึ้นพร้อมหมุน → ตก พร้อมควันผี/วิญญาณลอยออก (particle)
- **ฉาก:** ใยแมงมุมไหว, เปลวเทียนสั่น, ฝุ่นลอยในแสง, ฟักทองหายใจ (scale เบา ๆ)
- การ scale ต้องคงความคมของพิกเซล (ปัดเป็นจำนวนเต็มพิกเซลจอ) และ hitbox ไม่เปลี่ยน

**ฝั่งภาพ (Codex)** — ตาม handoff:
- เฟรมตัวละครเพิ่ม เฉพาะสเตจ 4: วิ่ง 8 เฟรม, กระโดด 3 จังหวะ (ขึ้น/จุดสูงสุด/ตก), ลงพื้น 1, แพ้ 3
- ถ้าภาพเพิ่มยังไม่มาหรือโหลดไม่ได้ → ใช้ 9 ท่าเดิม + motion ฝั่ง code แทน (ยังเล่นได้และยังลื่นขึ้น)

## 8. ภาพ เสียง และ fallback
